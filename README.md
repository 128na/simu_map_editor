# Simu Map Editor

Simutrans向けの、ブラウザ内で動作する地形エディタです。本実装を進めており、画像の読込、3D地形と水面の表示、ドラッグによる造成、Undo/Redo、BMP・PNG書き出しに対応しています。

## 起動

Node.js 22.18以降とnpmを用意して実行します。

```sh
npm ci
npm run dev
```

表示されたローカルURLをChromeまたはEdgeの最新版で開きます。初回は128四方の平坦なマップで始まります。地図名・サイズ・未保存状態は画面上部に表示します。ブラシの種類・半径・強さと真上／斜めの視点はブラウザへ記憶します。グリッド表示のON/OFFも記憶します。マップや互換設定は記憶しません。幅・高さ（タイル数）を指定して平坦な地形を新規作成するか、マップ画像を読み込んで開始します。新規作成・画像読込では確認後に現在の地形とUndo履歴を置き換えます。左ドラッグで連続造成し、右ドラッグで回転、ホイールでズームします。盛土・掘削は開始点の高さ±強さ、平坦化は開始点の高さに固定します。静止して0.5秒長押しすると盛土・掘削を繰り返せます。通常のドラッグは高さを固定し、長押しも含め離すまでを1回のUndoで戻せます。「なだらかにする」は近傍平均へ近づける平滑化で、強さ1〜8は平均化の反復回数です。「傾斜をならす範囲」1〜16（既定4）を広げると、段差や山の肩を広い幅にならします。「凹凸をならす」は平均化、「傾斜を緩める」はブラシ中央を開始点の高さに近づけて勾配を下げ、外周へ滑らかにつなぐ方式です。斜面条件を保つ補正はブラシ外へ波及する場合があります。Escapeで途中のドラッグを取り消します。海面表示は近似で、ゲームの湖・河川・砂浜生成は再現していません。画像から復元できない互換設定は、ゲーム側と合わせて指定してください。

履歴は画素差分をWorkerからIndexedDBへ非同期保存します。初期予算は未保存キュー64 MiB、保存済み512 MiB、最大1000操作で、予算設定はlocalStorageに保持します。Undo/Redoの読込中は編集を待機します。容量超過や保存失敗では造成を停止し、現在の地形と未保存履歴を保持します。画像を書き出すか、確認後に履歴を破棄して再開・RAM履歴へ切り替えられます。履歴はブラウザタブごとの一時データで、編集再開用セーブではありません。

書き出しはBMPまたはPNGボタンで選べます。PNGは8bitグレースケールの可逆圧縮で、BMPと同じ標高サンプルを保存します。互換設定はどちらの画像にも含まれないため、ゲーム側と合わせてください。

互換設定には検証対象Standardのソース版、設定候補、標高上下限を表示します。対象ゲーム版の標高上限127に対し、エディタは内部補正の余裕を残して125までに制限しています。高さ変換・範囲・係数・斜面条件の変更は、必要な補正を確認し履歴を破棄します。海面だけの変更は確認ダイアログなしで適用し、履歴と画像の未保存状態を維持します。画像値の変換条件を変えた場合は再書き出しが必要です。

画像読込時に、選択した互換設定で書出可能な標高と自然地形の斜面条件へ補正します。置換確認に補正画素数を表示し、補正があれば未保存として扱います。取り消すと現在の地形と履歴を保持します。元画像の未補正標高を保持する機能はありません。

左パネルに造成と表示、右パネルにファイルと互換設定を配置しています。履歴容量・操作ガイド・マップ詳細は折り畳めます。カーソル位置は左上原点の格子X/Yと、地形の表示標高で示します。グリッドは地形と水面へ表示し、遠距離では線のちらつきを抑えるため薄くなります。

入力は非インターレース8bitの灰階/RGB/不透明RGBA PNG、8bit・24bit BMP、PPM P6（最大値255）に対応します。PNGパレット・16bit・半透明、BMP RLEのdelta命令などは明示的に拒否します。各辺の上限は32,766、エディタの既定上限は総画素数67,108,864・ファイル256 MiBです。「表示品質・上限設定」で総タイル数（16,384〜268,435,456）、ファイル容量（1〜1024 MiB）、ブラシ半径上限（1〜256）、水面予算（自動または16〜256 MiB）、表示セル予算（約100万〜1600万、既定約400万）を変更し、ブラウザへ記憶できます。4096四方を超える場合は概算メモリを警告します。描画は分割し、カメラに映る範囲とズーム率に応じて表示予算を配分します。カーソルから離れた画面内の地形も詳細化し、画面外は粗く表示します。編集と保存は全解像度を維持します。水面予算の自動設定はマップ面積に応じた16〜64 MiBです。予算を下回るまで画像を粗くする処理は行わず、超過した更新は拒否します。これは現在の処理制限で、あらゆる端末での快適な操作を保証する値ではありません。

## 検証

```sh
npm run lint
npm test
npm run build
```

Windows上で、外部SimutransソースとMSYS2 MinGW64を使う検証:

```sh
npm run validate:heightmaps
npm run test:browser
powershell -NoProfile -File tools/validation/run-world-probe.ps1
```

ブラウザテストにはインストール済みのChromeとEdgeが必要です。 push・PRではPlaywright Chromiumで画面操作と履歴の回帰テストを実行します。同じ構成は `npx playwright install chromium` 後に `npx playwright test --config playwright.ci.config.ts` で実行できます。ゲーム全体の検証には追加でpakset・実行用データ・CMake/Ninja等が必要です。再現条件と検証の限界は [試作の検証記録](docs/records/2026-10-20_browser-prototype-validation.md) を参照してください。

## 性能計測

`npm run benchmark:cpu` は256・512・1024四方の造成をウォームアップ後5回計測し、`.validation/cpu-performance.json` を保存します。push・PRのCIでも実行し、結果を30日間保存します。現在は計測記録のみで、速度の閾値による失敗判定はありません。

実機での操作計測はPowerShellで実行します。

```powershell
$env:VALIDATE_OPERATIONS='1'
npm run test:browser -- --grep 'operation performance' --project chrome
```

連続ドラッグ中の1更新ごとのCPU待ち時間は、`VALIDATE_INTERACTION=1` を設定して `npm run test:browser -- --grep 'continuous sculpting' --project chrome` で計測できます。`.validation/interaction-*.json` に初回・中央値・95%点と処理内訳を保存します。`--repeat-each 3` で試行を分け、`INTERACTION_BASELINE_REF` に比較元コミットSHAを指定すると、API互換のある旧版の地形処理・格子更新・地形描画・水面モジュールを同じ画面操作で比較します。セッションAPIや分割水面モジュール追加前のコミットは差替え対象にできません。APIが異なる版は、それぞれのチェックアウトで計測してJSONを保存・比較してください。これはローカルGPUでの応答計測で、操作全体の時間や見た目のfpsとは別の指標です。従来の操作計測JSONにも更新内訳を追加保存します。ブラシは `INTERACTION_RADIUS`（1〜40）、`INTERACTION_AMOUNT`（1〜8）、`INTERACTION_TOOL`（raise/lower）で変更でき、JSONに条件と水面処理の時間も保存します。例えば40・8・lowerは海岸線が変化する広い掘削の検証です。

ローカルGPUで4096四方のドラッグ目標を検証する場合は、追加で `$env:DRAG_BUDGET_MS='1000'` を設定します。1秒の判定は指定時だけ有効です。標準は1024・2048・4096四方です。`PERF_SIZES` 環境変数でカンマ区切りのサイズを指定できます。GitHub Actionsの `browser-performance` は手動起動でサイズを選択し、Playwright Chromiumで計測します。通常ランナーの描画結果をローカルGPUの速度と直接比較しないでください。CIと同じ専用設定は `npx playwright install chromium` 後に `npm run benchmark:browser` で実行できます（`VALIDATE_OPERATIONS=1` が必要）。

mainへのpushとmainでの手動ブラウザ計測が成功すると、[性能記録Issue](https://github.com/128na/simu_map_editor/issues/1) に結果表とJSONをコメントします。PRからは投稿しません。成果物が期限切れになっても、コメント内の生データから再集計できます。同一の計測種別・CI実行ID・再実行番号は二重投稿せず、再実行番号が異なる測定は別記録として残します。

GitHub CLIでリポジトリを読める認証を済ませてから `npm run performance:export` を実行すると、公式CIボットの記録を取得し `.validation/performance-history.csv` へ集約します。引数で出力先を変更できます（例: `npm run performance:export -- .validation/history.csv`）。1行は1実行・サイズ・操作で、単位はmsです。CPU/ブラウザ、計測バージョン、環境を分けて比較してください。数値は平均せず、生の各試行から中央値を再計算します。ローカル計測は識別情報を保存しますが、自動ではIssueへ投稿しません。

## ドキュメント

ドキュメントは [docs/README.md](docs/README.md) の規約に従います。初期調査は `docs/records/`、意思決定は `docs/adr/` に保存し、調査の続報は新しい記録として追加します。

水面表示の自動CPU配列予算はマップ面積に応じて16〜64 MiB（4096四方で16 MiB、8192四方で64 MiB）です。画面から16〜256 MiBの固定予算も選べます。GPU側のコピーと更新時の一時配列は別途必要です。水面の大メモリ検証は `VALIDATE_LARGE_WATER=1` を設定し、`node --experimental-strip-types --test tests/water-surface.test.ts tests/water.test.ts` で実行できます。
