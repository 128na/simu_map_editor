# マップ面積上限の拡張検証

## 目的 / 発端

利用者の端末では1024四方を遅さなく操作できたため、4096四方を試せるよう面積制限の拡張を依頼された。

## 分かったこと（事実）

各辺4096とは別に総画素数1,048,576を制限していた。総画素数を16,777,216へ変更した。新規作成と画像読込は共通の寸法検証を使う。4096四方の24bit BMPは約48 MiBになるため、画像ファイル上限も16から64 MiBへ変更した。水面配列の16 MiB制限は維持した。

RTX 4070 Ti / ANGLE Direct3D11のChrome・Edgeで4096四方の平坦地を実際の新規作成UIから作成し、33,554,432三角形の描画を確認した。作成操作開始から描画計測終了までChrome 7,272 ms、Edge 7,876 msだった。メッシュCPU配列は1,006,927,908 bytes（約960 MiB）。GPUコピー、標高、正規化用配列、旧地形、Undo履歴はこれに含まない。

## 検証と再実行

単体テスト27件、lintと本番ビルドが成功した。寸法境界テストは4096四方を許可し4097辺を拒否する条件へ更新した。大サイズ検証はメモリ負荷が高いため通常のブラウザテストとは分け、PowerShellで `$env:VALIDATE_LARGE_MAP='1'; npm run test:browser -- --grep '4096-square'` を実行する。Chrome・Edgeの2件が成功した。測定JSONとスクリーンショットは `.validation/large-map-*` に保存した。

## 推測・未確認事項

今回の上限は利用者が試すための拡張である。4096四方の連続造成、Undoの積み重ね、複雑な海岸、大サイズ画像の往復、端末間差、GPU込みピークメモリは未検証。短い静止描画計測から実際のFPSや編集性能は判断しない。全解像度メッシュを毎回再構築する方式と20操作分の全標高履歴は変更していない。[サイズ制約のADR](../adr/0007-editor-size-and-resource-budget.md)の性能受け入れ条件を満たしたとは扱わない。
