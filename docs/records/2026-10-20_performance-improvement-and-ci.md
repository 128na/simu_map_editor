# 地形編集の性能改善とCI計測の追加

## 発端と実施内容

利用者の依頼に従い、先に性能改善を行い、測定で改善を確認した後にCI計測を追加した。

造成の全地図走査アルゴリズムは維持し、TypedArray生成callbackと間接関数呼出を通常ループへ置き換えた。描画は同寸法の頂点・色・indexバッファを再利用し、変わった頂点と隣接faceの法線だけ更新した。描画前に複数回更新した範囲も保持してGPUへ送る。ポインター判定は全三角形のraycastから、XZ格子を辿って同じ三角形へ交差判定するDDAへ置換した。水面の予算超過検証は可視バッファの更新前に行う。

## 同条件での結果（秒）

前回と同じChrome・RTX 4070 Ti、平坦地、半径8、各ツール197画素変更、3回中央値。ドラッグは7点、回転は10stepの自動操作全体時間。

| サイズ | 盛土 前→後 | 平坦化 前→後 | ドラッグ 前→後 | 回転 前→後 |
| --- | --- | --- | --- | --- |
| 1024² | 0.50 → 0.06 | 0.79 → 0.07 | 5.95 → 0.53 | 0.68 → 0.17 |
| 2048² | 2.48 → 0.23 | 3.61 → 0.27 | 28.51 → 1.77 | 2.55 → 0.18 |
| 4096² | 9.34 → 0.88 | 13.78 → 1.08 | 103.23 → 6.78 | 10.47 → 0.17 |

[改善後の生データ](2026-10-20_performance-improvement-results.json)と[改善前の記録](2026-10-20_operation-performance.md)を保存した。同期JS時間とUI自動操作時間を同一視せず、GPU完了時間や操作中FPSとは扱わない。

4096四方の処理内訳は、造成core約0.36〜0.59秒、格子生成約0.23〜0.26秒、量子化集計と水面生成約0.17〜0.23秒、geometry更新等約0.04〜0.11秒だった。まだ全地図の走査・正規化・配列コピーが残る。メッシュ常駐CPU容量も約960 MiBのままであり、GPUと履歴込みのピークは未測定。長時間編集、20履歴、複雑な海岸での性能を保証しない。

## 正しさの検証

単体32件、Chrome・Edge合計24件の通常ブラウザ検証、1024/2048/4096の操作計測3件が成功した。単体は独立全点対斜面oracle、Three標準raycastとの1,620 ray比較、差分法線と全再計算法線の比較、未送信GPU範囲の保持を含む。ブラウザはnative格子照合・画像往復・造成・取消・Undo/Redo・水面エラー時の原本維持を含む。lint・型チェック・本番ビルド成功。500 kB超チャンク警告は残る。レビューの未送信範囲上書き指摘は修正し回帰を追加、未解消Must/Shouldなし。

## CIでの計測

push/PRの既存workflowへ `npm run benchmark:cpu` を追加した。256・512・1024四方、ツールごと独立flatmap、warmup1回を除いた5試行の中央値をJSONに保存し30日間artifactとして保持する。速度の失敗閾値と過去結果自動比較は導入せず、まずrunner上のばらつきを収集する。

手動 `browser-performance` workflowは1024/2048/4096を選択し、専用Playwright設定でChromiumだけを実行する。外部Simutrans実行ファイルを要する通常のnative比較テストは混ぜない。結果は失敗時も保存する。実装は [Playwright CI手順](https://playwright.dev/docs/ci) と [GitHub成果物仕様](https://docs.github.com/en/actions/concepts/workflows-and-actions/workflow-artifacts) を確認した。YAML構文をローカルで確認した。

GitHub runner上ではまだ実行していない。ローカルGPUとの直接速度比較はしない。大サイズでrunnerのメモリやWebGL制約に達する可能性は未確認。CIのCPU測定をエディタ/GPU応答の代用にはしない。
