# 本実装への移行と画面・設定管理の整備

## 目的 / 発端

利用者が検証用エディタの履歴退避と取り込み正規化を確認し、本実装への移行を指示した。検証済みの地形・画像・履歴処理を維持し、画面構成と設定の責務を分離する段階から開始した。

## 分かったこと（事実）

画面テンプレートをeditor-layoutへ分離し、起動時のデモ地形を128四方の平坦なマップへ変更した。地図名・寸法・未保存状態をヘッダーとタイトルへ反映し、BMP書出名は読込ファイル名を引き継ぐ。取消・読込失敗では現在の名前を保持する。

[ADR-0009](../adr/0009-image-save-and-local-preferences.md)に沿い、版付きの小さい設定としてツール・ブラシ半径・強さ・真上／斜め視点を保存した。未知版・破損JSON・不正フィールド・ストレージ利用不可では初期値で動く。互換設定と地形・履歴はこの設定へ保存しない。

push・PRでChromiumの画面操作・非同期履歴・タブ分離を自動検証するCIを追加した。ネイティブSimutransが必要な互換照合は引き続きローカルChrome/Edgeの検証に残す。

単体63件、Chrome/Edge計52件、lint・型検査・ビルドが成功した。レビューの指摘を受け、読込失敗・取消後の地図名と書出名の保持も画面回帰テストへ加えた。

## 推測・未確認事項

これは初期リリース全体の完了ではない。4096超の警告付き対応と分割描画、互換プロファイルの確定、長時間・大範囲編集、配布形態の検討が残る。[初期リリースの課題](https://github.com/128na/simu_map_editor/issues/3)へ集約した。現在の4096²の上限は維持する。

## 結果どうしたか

検証用コードを破棄して作り直す方式は採らず、試作で確かめた中核処理に回帰テストを付けて継続利用する。UIと設定を分け、以降の画面変更から互換処理への影響を抑える構成へ移行を開始した。
