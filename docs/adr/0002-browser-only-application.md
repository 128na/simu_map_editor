# ADR: バックエンドを持たないブラウザアプリとして提供する

> ステータス: Accepted (2026-10-20)
> 由来: [要件と初期調査](../records/2026-10-19_simutrans-heightmap-research.md)

## 背景と問題

ユーザーはブラウザで地形を編集し、画像を入出力できることを求めている。サーバー側の保存は不要であり、地形編集のためにアカウントやデータベースを必要とする理由がない。

## 決定

静的配信できるブラウザアプリとし、読込・編集・変換・書出を利用者の端末内で完結させる。ローカルファイルの選択とダウンロードを基本の入出力とし、バックエンド、ログイン、クラウド保存は導入しない。

## 検討した代替案と却下理由

- サーバーで地形変換と保存を行う: 運用と通信の依存が増え、バックエンド不要という要件に合わない。
- デスクトップアプリとして提供する: 配布・更新・OS対応が必要になり、ブラウザで利用する要件に合わない。
- ブラウザ固有のファイルシステムAPIを必須にする: 対応環境を狭めるため、標準のファイル選択とダウンロードで成立させる。

## 影響・トレードオフ

処理性能と扱える地形サイズは端末のCPU・GPU・メモリに依存する。バックエンド不要と、配信サーバー不要・file URLでの起動・完全オフライン対応は別の条件であり、後者はここでは約束しない。

ブラウザ内の自動保存や編集再開用ファイルは必須にせず、データ消失対策として必要になった時点で別の判断を残す。共同編集や端末間同期が要件になった場合に再検討する。
