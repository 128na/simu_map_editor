# ADR: 大サイズを警告し全解像度データと予算付き分割描画を分ける

> ステータス: Accepted (2026-10-20)
> 由来: [統合検証記録](../records/2026-10-20_profiles-and-large-maps.md)

## 背景と問題

[ADR-0012](0012-large-map-warning-and-history-budget.md)の大サイズ方針を実装するには、全タイルのメッシュが4096四方だけで約960 MiBを占める構成を変える必要がある。ゲームGUIの上限まで配列を無条件に確保することはできない。

## 決定

対象StandardのGUI軸上限32,766と、エディタの資源上限67,108,864画素を分ける。標準の各辺4096・4096²タイルを超える場合は、作業配列の概算と端末差を警告して続行判断を求める。画像はヘッダを検査して展開前に判断する。入力ファイルは256 MiBを上限とする。

描画は256タイル単位のチャンクとし、全体は約100万セルの予算内で間引く。カーソル周辺の最大4チャンクを詳細化し、LOD境界にスカートを付ける。標高のsource、表示用格子、座標判定、画像書出は全解像度を維持する。

## 検討した代替案と却下理由

全解像度の単一メッシュを拡大するとRAM/GPU負荷が面積に比例する。画像自体を縮小すると保存地形を変えてしまう。全体を間引くだけでは局所造成が見えないため、編集周辺の詳細化を組み合わせる。

## 影響・トレードオフ

遠景は近似表示となり、スカートは隙間を隠す方式である。隣接LODの完全な面一致や全域の常時詳細表示を保証するものではない。全解像度の標高・格子・コピー・水面処理は残り、資源上限以内でも全端末で確保できる保証はない。大きな表示領域ではdraw call数も増える。複雑な海岸や長時間編集の評価を継続する。
