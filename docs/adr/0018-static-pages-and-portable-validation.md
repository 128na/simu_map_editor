# ADR: 静的配信と外部検証環境を分離する

> ステータス: Accepted (2026-10-21)

## 背景と問題

ブラウザ完結のエディタを公開する際、開発端末のドライブ配置やSimutransのビルド環境を利用者へ要求すると、実行と検証の再現性が損なわれる。

## 決定

GitHub Pagesへ検証済みの静的成果物だけを配信し、アセットとWorkerは相対参照にする。通常のフロントエンド検証と、明示的に有効化する実ゲームのネイティブ検証を分離する。後者の外部パスは環境変数から受け取り、対象ソースとハッシュの検査は維持する。

## 検討した代替案と却下理由

- 専用バックエンド: ブラウザ内の画像編集に必要なく、運用負担が増える。
- リポジトリ名を埋め込む配信パス: 別名のリポジトリや別の配信先への移動を難しくする。
- 全テストで実ゲーム環境を必須にする: UIのみの開発にも大きな外部依存を要求する。

## 影響・トレードオフ

通常の検証だけでは実ゲーム互換を再確認できないため、互換処理を変更する際はネイティブ検証を別途実行する。ブラウザ保存領域は配信オリジンごとに分かれ、ローカルから公開先へ一時履歴は移行しない。
