# 画像変換を操作ごとのWorkerへ分離する

> ステータス: Accepted (2026-10-21)

## 背景

8192四方の画像変換と正規化では、メインスレッドを数秒占有するため取消ボタンを置くだけでは応答しない。元の地図を破壊せずに失敗・取消から復帰する必要がある。

## 決定と理由

読込・寸法確認・デコード・正規化・画像生成は操作ごとのWorkerで実行する。取消はWorkerを終了し、処理結果だけを転送する。書出元の配列は転送せず複製するため、一時メモリの増加を許容して元の地図を保持する。

各段階を表示し、実測できない進捗率は表示しない。寸法確認のユーザー待ちは処理タイムアウトから除く。結果反映前に地図・互換設定・版を照合し、古い結果を破棄する。

描画資源の最終反映は同期的な確定処理として残す。この段階で取消可能と表示すると実態と食い違うため、確定前まで取消可能とし、確定中は明示する。描画反映自体の分割は別途計測して判断する。

## 帰結

Worker内部の計算時間そのものは短縮しない。配列複製とWorker起動の費用が追加される。ブラウザのダウンロード受け渡し成功を保存済み判定とし、実ディスクへの保存完了は確認できない。
